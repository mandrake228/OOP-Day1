# OOP-Day7

Учебный проект курса «База ООП»: модель банка.

- День 1 — базовая модель: абстрактный счёт и обычный счёт.
- День 2 — три продвинутых типа счетов: сберегательный, премиальный, инвестиционный.
- День 3 — клиент, банк и защита: вход по паролю, блокировка, ночной запрет.
- День 4 — транзакции: запись об операции, очередь с приоритетами и процессор.
- День 5 — аудит и риск-анализ: журнал аудита, оценка риска, блокировка опасных
  операций и отчёты.
- День 6 — вся система вместе: приём транзакций, журнал событий, кабинет клиента
  и отчёты.
- День 7 — отчёты и графики: текст, JSON, CSV и картинки PNG.

## Типы счетов

| Тип | Сколько можно снять | Особенности |
| --- | --- | --- |
| `BankAccount` | весь баланс | лимит на одно снятие 100 000 |
| `SavingsAccount` | баланс минус минимальный остаток | `apply_monthly_interest()` начисляет проценты за месяц |
| `PremiumAccount` | баланс плюс лимит овердрафта | лимит на одно снятие 1 000 000, комиссия за каждое снятие |
| `InvestmentAccount` | баланс минус сумма в портфеле | `invest()` вкладывает в `stocks`, `bonds`, `etf`; `project_yearly_growth()` считает прирост за год |

Каждый новый тип наследует `BankAccount` и переопределяет `withdraw()`,
`get_account_info()` и `__str__()`. Любой счёт умеет менять статус: `freeze()`,
`unfreeze()`, `close()`.

## Клиент и банк

Клиент `Client` проверяет свои данные при создании. Человек моложе 18 лет клиентом
не становится.

| Метод банка | Что делает |
| --- | --- |
| `add_client(client, password)` | регистрирует клиента вместе с паролем |
| `open_account(client_id, тип, ...)` | открывает клиенту счёт любого из четырёх типов |
| `freeze_account(номер)`, `unfreeze_account(номер)`, `close_account(номер)` | меняют статус счёта |
| `authenticate_client(client_id, password)` | проверяет вход клиента |
| `search_accounts(...)` | ищет счета по клиенту, имени владельца, типу, статусу, валюте |
| `get_total_balance(...)` | сумма на незакрытых счетах в одной валюте |
| `get_clients_ranking(...)` | клиенты по убыванию суммы в одной валюте |
| `get_suspicious_actions(...)` | журнал подозрительных действий |
| `get_account(номер)`, `has_account(номер)`, `now()` | счёт по номеру, есть ли такой счёт, время по часам банка |
| `check_operation_time(операция, номер)` | ночью отказывает в операции со счётом и помечает попытку |
| `get_owner_id(номер)` | ID клиента, которому открыт счёт |
| `get_client_info(client_id)` | ID, ФИО и статус клиента; только чтение |
| `check_client_active(client_id, операция, номер)` | заблокированному клиенту отказывает и помечает обращение; номер счёта можно не указывать |

## Защита

- Три неверных пароля подряд блокируют клиента. Заблокированный клиент не может
  ни войти, ни провести операцию: его транзакции банк отклоняет.
- С 00:00 до 05:00 банк не выполняет операции. Работают только заморозка счёта и чтение
  данных. Запрет действует и на транзакции: перед движением денег процессор спрашивает
  банк.
- Неверные пароли, обращения от имени заблокированного клиента и ночные попытки
  попадают в журнал подозрительных действий.
- Пароль в открытом виде не хранится: банк держит только соль и хеш.

## Транзакции

Транзакция `Transaction` — запись об одной операции с деньгами. Она хранит ID, тип,
сумму, валюту, комиссию, отправителя, получателя, статус, причину отказа, число попыток
и две отметки времени.

| Тип транзакции | Что происходит |
| --- | --- |
| `deposit` | деньги зачисляются на счёт получателя |
| `withdrawal` | деньги списываются со счёта отправителя |
| `transfer` | деньги переходят с одного счёта банка на другой |
| `external_transfer` | деньги уходят на счёт в другом банке, комиссия 1% |

| Статус | Что значит |
| --- | --- |
| `pending` | ожидает исполнения |
| `completed` | выполнена |
| `failed` | отклонена, причина записана в `failure_reason` |
| `cancelled` | отменена до исполнения |

Очередь `TransactionQueue`:

- `add(transaction, priority=..., run_at=...)` — ставит в очередь; приоритет `high`,
  `normal` или `low`; `run_at` откладывает исполнение до нужного времени;
- `cancel(ID)` — отменяет транзакцию, пока она не исполнена;
- `reschedule(ID, run_at)` — переносит время исполнения;
- `get_entries()` и `len(queue)` — что стоит в очереди и сколько.

Процессор `TransactionProcessor`:

- `process_queue(queue)` — исполняет все готовые транзакции очереди;
- `process(transaction)` — делает одну попытку исполнить одну транзакцию;
- `calculate_fee(transaction)` — комиссия: 1% за внешний перевод, иначе 0.00;
- `convert(amount, source, target)` — пересчёт суммы по таблице учебных курсов;
- `get_errors(...)` — журнал ошибок: каждая неудачная попытка с причиной.

Правила исполнения:

- перевод не уводит счёт в минус; исключение — премиальный счёт в пределах овердрафта;
- замороженный счёт не отдаёт и не получает деньги;
- за внешний перевод берётся комиссия 1% сверх суммы;
- если счёт заморожен или не хватило денег, попытка повторяется через минуту, всего
  не больше трёх попыток; остальные отказы окончательные;
- с 00:00 до 05:00 транзакции не исполняются: отказ окончательный, а попытка попадает
  в журнал подозрительных действий банка; транзакцию, отложенную в очереди до утра,
  ночной запуск не трогает;
- транзакцию заблокированного клиента банк отклоняет: отказ окончательный, попытка
  попадает в журнал подозрительных действий; перевод такому клиенту от другого
  клиента проходит.

## Аудит и риск-анализ

Журнал аудита `AuditLog(file_path=...)`:

- `add(время, уровень, событие, сообщение, client_id=..., transaction_id=..., data=...)`
  — добавляет запись; уровни важности `info`, `warning`, `error`, `critical`; события
  `risk`, `completed`, `refused`, `blocked`, `queued`, `cancelled`;
- `filter(min_level=..., event=..., client_id=..., transaction_id=..., since=...,
  until=...)` — отбирает записи по условиям; без условий возвращает все;
- `get_records()` и `len(log)` — все записи и их число;
- если указан файл, каждая запись сразу дописывается в него строкой; файл никогда
  не затирается;
- записи отдаются копиями на всю глубину: изменить журнал через полученную
  запись нельзя;
- `AuditView(log)` — тот же журнал только для чтения: `filter`, `get_records`,
  `len` и `file_path`, без `add`.

Анализатор риска `RiskAnalyzer(bank)`: `assess(transaction)` возвращает сигналы,
сумму баллов и уровень риска. Транзакция оценивается один раз. Оценка принадлежит
самой транзакции, а не только её ID: другой транзакции с тем же ID анализатор
оценку не выдаёт и отказывает ошибкой `DuplicateTransactionIdError`.

| Сигнал | Когда срабатывает | Баллы |
| --- | --- | --- |
| `large_amount` | сумма от 50 000 рублей; другая валюта — по курсу | 3 |
| `frequent_operations` | у клиента уже три операции за последние десять минут | 2 |
| `new_recipient` | перевод на чужой счёт, куда клиент ещё не переводил | 1 |
| `night_operation` | с 00:00 до 05:00 по часам банка | 2 |

Уровень риска: 0–1 балл — `low`, 2–3 — `medium`, 4 и больше — `high`.

Защищённый процессор `SecureProcessor(bank, analyzer, audit)` — наследник
`TransactionProcessor`:

- перед движением денег спрашивает анализатор; транзакцию с высоким риском блокирует:
  статус `failed`, ошибка `HighRiskError`, деньги не двигаются, повторов нет;
- транзакцию с ID, который уже занят другой транзакцией, отклоняет так же: статус
  `failed`, ошибка `DuplicateTransactionIdError`; запись об оценке риска для неё
  не появляется;
- транзакции с низким и средним риском исполняет по правилам дня 4;
- правила банка действуют на все транзакции: ночью и для заблокированного клиента
  опасную операцию и операцию с чужим ID тоже отклоняет банк, и попытка попадает
  в журнал подозрительных действий;
- оценку риска, исполнение, отказы и блокировки записывает в журнал аудита;
  у исполненной транзакции в данных записи `completed` — балансы её счетов
  в этом банке до и после (`moves`).

Отчёты `AuditReport(audit)` строятся только по журналу аудита:

- `suspicious_operations()` — операции со средним и высоким риском;
- `client_risk_profile(client_id)` — риск-профиль клиента: операции, уровни, сигналы,
  блокировки;
- `error_statistics()` — статистика отказов: временные, окончательные, блокировки,
  классы ошибок.

## Банковская система

`BankSystem(bank, audit_file=...)` собирает вокруг готового банка журнал аудита,
анализатор риска, защищённый процессор, очередь и отчёты аудита:

- `submit(тип, сумма, currency=..., sender=..., recipient=..., priority=..., run_at=...)`
  — создаёт транзакцию, ставит её в очередь и возвращает её ID; ID даёт система:
  `T0001`, `T0002` и дальше;
- `cancel(ID)` — отменяет ожидающую транзакцию; `run()` — исполняет готовые;
  `get_queue()` — что ждёт в очереди;
- `get_transaction(ID)` и `get_transactions(status=..., client_id=...)` — данные
  транзакций вместе с клиентом, приоритетом и оценкой риска;
- приём в очередь и отмена записываются в журнал аудита событиями `queued`
  и `cancelled`, исполнение и отказы — как в дне 5;
- `top_clients(3)`, `transaction_statistics()`, `total_balance()` — топ клиентов,
  статистика транзакций и общий баланс; суммы в валюте пересчитываются в рубли
  по курсам процессора;
- `login(client_id, пароль)` — вход в кабинет клиента по правилам входа банка;
- `to_rub(сумма, валюта)` — пересчёт в рубли по курсам процессора;
  `client_total_rub(client_id)` — сумма клиента в рублях, как в топе;
- `client_history(client_id)` и `client_suspicious_operations(client_id)` —
  операции клиента с направлением и масками и его подозрительные операции;
  ими пользуются кабинет и отчёты;
- свойство `audit` отдаёт журнал только для чтения (`AuditView`): дописать
  запись в журнал системы снаружи нельзя.

Кабинет клиента `ClientSession` только читает: `accounts()` — счета клиента,
`history(account_id=None)` — операции по его счетам с направлением `in`, `out`
или `own` (чужие номера скрыты маской), `suspicious_operations()` — его операции
со средним и высоким риском. Если клиента заблокируют после входа, кабинет
перестаёт отвечать. Причину отказа чужого входящего перевода получатель
не видит: в ней данные счёта отправителя.

## Отчёты и графики

`ReportBuilder(system)` строит отчёты по банковской системе. У всех трёх отчётов одна
структура: заголовок, время формирования, итоги, таблицы и описания графиков.

| Отчёт | Главная таблица | Ещё таблицы | Графики |
| --- | --- | --- | --- |
| `client_report(client_id)` | `history` — операции клиента | `accounts`, `moves` | движение баланса, счета |
| `bank_report()` | `accounts` — все счета под маской | `totals`, `clients` | доли валют, клиенты |
| `risk_report()` | `suspicious` — подозрительные операции | `errors`, `profiles` | уровни риска, отказы |

- `render_text(отчёт)` — отчёт текстом;
- `export_to_json(отчёт, путь)` — весь отчёт в JSON: деньги строкой, время в ISO 8601;
- `export_to_csv(отчёт, путь, table=None)` — одна таблица в CSV, без имени — главная;
  файл в UTF-8 с BOM, чтобы Excel узнал кириллицу; в Excel его открывают через
  «Данные → Из текстового/CSV-файла»;
- `save_charts(отчёт, папка)` — графики отчёта в PNG 800 на 500 точек.

Папка для файлов должна уже существовать. Экспорт принимает только отчёт той формы,
которую строит построитель, и не пишет поверх файла журнала аудита. Отчёты только
читают: ничего не меняют, работают и ночью. Полные номера счетов есть только в отчёте
по клиенту, у его собственных счетов; остальное — маской.

Итог в рублях считается как в дне 6: сначала сумма по валюте, потом пересчёт. Столбец
`balance_rub` пересчитывает каждый счёт отдельно, поэтому сумма столбца может
отличаться от итога на копейку.

Графикам нужен matplotlib. Он ставится в окружение проекта, а не в системный Python:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

```

python demo_day3.py
python demo_day4.py

```

Нужен Python 3.11 или новее. Дням 1–6 ничего устанавливать не надо. Дню 7 нужен
matplotlib в окружении проекта `.venv`, см. «Отчёты и графики». Чтобы оставить
отчёты и графики дня 7, передайте папку: `.venv\Scripts\python demo_day7.py reports`.

Каждая демонстрация сама себя проверяет. Если модель ведёт себя как ожидалось,
последняя строка сообщает об успехе, а код завершения равен 0. Демонстрации дней 3–7
задают время сами, поэтому их результат не зависит от того, когда их запустили.
Демонстрации дней 5–7 пишут файлы во временную папку и убирают их за собой.
